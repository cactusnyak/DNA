Hi, there is some problem: I can registrate vie Yandex, but if I will remove that user (for example, via 'remove accaunt' button), next attemps of registration via Yandex doesn't work. This is my dialog with Chat GPT about this problem:

итак, увидел проблему: если удалить акк, зарегестрированный через яндекс, то потом регистрация/вход не работает. Обидно, что не так?

Это очень похоже на одну из классических ошибок OAuth-интеграций.

Самая вероятная причина такая:

При первой регистрации через Яндекс создаётся запись вроде:
User
id = xxx
provider = YANDEX
providerId = 123456789
Ты удаляешь пользователя.
Потом Яндекс снова присылает тот же самый providerId.
Backend пытается найти пользователя по нему, находит либо "мёртвую" запись (если используется soft delete), либо пытается привязать существующую сущность, и логика попадает в неправильную ветку.
Возможные причины по вероятности
1. Soft Delete (самая вероятная)

Если удаление происходит через:

deletedAt = new Date()

или

isDeleted = true

то поиск пользователя может выглядеть так:

findUnique({
  where: {
    provider: 'YANDEX',
    providerId,
  },
})

Он всё ещё находит удалённую запись.

Если потом код говорит:

if (user) {
    login(user);
}

или

throw UserAlreadyExists;

то повторная регистрация невозможна.

2. Не удаляется OAuth Account

Если у тебя отдельная таблица вроде

OAuthAccount
-------------
provider
providerUserId
userId

то мог удалиться User, но осталась запись:

provider = YANDEX
providerUserId = XXXXX
userId = deletedUser

Следующая авторизация находит именно её.

Это вообще самая частая проблема в схемах вида:

User
OAuthAccount
3. UNIQUE индекс

Например

UNIQUE(provider, providerUserId)

После удаления пользователя запись остаётся.

Создать новую уже нельзя.

4. Логика регистрации

Очень часто встречается такой код:

const user = findByProviderId(...);

if (user) {
    return login(user);
}

if (emailExists) {
    throw ...
}

createUser(...)

Если findByProviderId() возвращает невалидного пользователя, создание уже не происходит.

Что проверить

Посмотри БД после удаления.

Если таблица одна:

SELECT *
FROM "User"
WHERE provider = 'YANDEX';

или

SELECT id,
       deletedAt,
       provider,
       providerId,
       email
FROM "User";

Если отдельная таблица:

SELECT *
FROM "OAuthAccount";

После удаления пользователя там не должно оставаться записей, привязанных к нему.

Каким должно быть правильное поведение

После удаления аккаунта должны удаляться:

User
RefreshToken
OAuthAccount
Session
ReferralCode (если требуется)
всё, что связано FK

После этого пользователь должен выглядеть для системы как новый.
