# Database seeds

Each seed scenario lives in its own directory so new scenarios can be added
without mixing their data, scripts, or binary assets.

```text
seeds/
├── default/
│   ├── seed.ts
│   ├── seed-images.ts
│   └── assets/
└── production/
    ├── seed.ts
    ├── assets/products/
    └── backups/
```

- `default` creates development/demo data. Its image step currently downloads
  remote demo images and writes the runtime copies to `uploads/images`.
- `production` imports the production catalog. Its source images are versioned
  under `assets/products` and are copied to `uploads/images` by the seed.
- `uploads` is runtime storage, not a seed source. Files uploaded through the
  API and generated by seed runs may coexist there, so it must not be treated
  as immutable seed data.
- Scenario-specific backups stay beside the scenario that produced them.

Run scenarios through the npm scripts in `api/package.json`.
